# reply-reaction

他人の返信を読んだことを、リアクションで相手に伝える。

付けるのは次のどちらか 1 つ。読んだ返信には必ずどちらかを付ける。

| 返信の内容 | リアクション | `content` |
|---|---|---|
| 異議なく同意できる | 👍 | `+1` |
| 読んだだけ | 👀 | `eyes` |

## 判断の基準

👍 は「読んだ」ではなく「同意した」という意思表示として相手に伝わる。同意できないものに付けてはいけない。

次のどれかに当たるなら 👍 ではなく 👀 にする。

- 内容の一部にでも異論や疑問がある
- 書かれた事実（「有効にした」「直した」など）を、まだ自分で確かめていない
- 同意を示す種類の内容ではない（報告や質問、依頼）
- 返信が自分たちの提案と食い違う方針を示している

事実を確かめられるなら、先に確かめてから判断する。確かめた結果、同意できれば 👍 にする。

## 付けないもの

- 自分（`gh api user --jq .login` のアカウント）のコメント
- bot のコメント（`user.type` が `Bot`、または login が `[bot]` で終わる）
- すでに自分が同じリアクションを付けているコメント（スクリプトが自動で飛ばす）

## 付け方

同梱スクリプトにコメントの URL とリアクションを渡す。

```bash
"${CLAUDE_SKILL_DIR}/scripts/react.sh" <コメントの URL> <+1|eyes>
```

使える URL は次の 2 種類。

| URL の形 | 対象 | 叩く API |
|---|---|---|
| `https://github.com/<owner>/<repo>/(issues\|pull)/<n>#issuecomment-<id>` | Issue / PR の会話欄のコメント | `issues/comments/<id>/reactions` |
| `https://github.com/<owner>/<repo>/pull/<n>#discussion_r<id>` | PR の行コメント（レビューコメント） | `pulls/comments/<id>/reactions` |

PR のレビュー本体（Approve / Request changes の総評）には、API でリアクションを付けられない。付けられないことをユーザに伝える。

`gh api` の結果に含まれる `html_url` をそのまま渡せばよい。

スクリプトは次のことをする。

- 付ける前に、コメントの投稿者が自分か bot なら止める（終了コード 3）
- 自分がすでに同じリアクションを付けていれば、何もせず成功で返す
- 付けたら `<content> <comment_id> <投稿者>` を 1 行出す

## 報告

ユーザへの報告には、リアクションごとに次を書く。

- どのコメントに、どちらを付けたか（コメントへのリンク）
- そう判断した理由を一言

👀 にしたときは、引っかかった点（異論、未確認の事実、相手への確認事項）もあわせて報告する。

## 終了コード

| コード | 意味 |
|---|---|
| 0 | 付けた、またはすでに付いていた |
| 2 | 引数が違う（URL の形が対応外、リアクションが `+1` / `eyes` 以外） |
| 3 | 自分か bot のコメントなので付けなかった |
| 4 | GitHub API の呼び出しに失敗した |

## テスト

```bash
bash "${CLAUDE_SKILL_DIR}/scripts/tests/test-react.sh"
```

`gh` を偽物に差し替えて、URL の解釈・自分と bot の除外・二重付けの回避・叩く API を確かめる。ネットワークには出ない。
